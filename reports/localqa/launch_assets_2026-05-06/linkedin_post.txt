I’m launching LocalQA v0.1 alpha.

Agent for your agents.

LocalQA is a local Bonsai-backed sidecar that helps frontier coding agents handle logs, browser evidence, project memory, and context cleanup before spending cloud tokens.

The problem I kept running into: coding agents are powerful, but they waste a lot of expensive context on low-value evidence work: raw logs, repo scans, browser traces, DOM dumps, repeated terminal output, and rediscovering what was already tried yesterday.

LocalQA adds a local layer between the frontier model and noisy evidence.

The frontier model still plans and writes code. Bonsai handles noisy local evidence before the frontier model sees a compact verified report.

Launch surfaces:
- MCP-first public interface
- OpenCode plugin for deeper native workflows

Current capabilities:
- one local sidecar tool: local_agent_run
- directed execution where the main model specifies exact steps
- strict tool mode
- local project memory
- log/repo/browser evidence cleanup
- handoff redaction
- OpenCode vault-handle follow-up via answer_from_handle

Launch proof:
- 53.39% fewer fresh input tokens in one real OpenCode provider telemetry A/B test
- 74.04% reduction in controlled A/B workflow benchmark, 3/3 quality gates maintained
- 302,772 -> 8,842 tokens in long-horizon benchmark, 9/9 quality gates, 9/9 memory writes

Repo: https://github.com/Ar5en1c/localqa

This does not replace frontier models. It makes them easier to use well by giving them cleaner local context and memory.

Alpha caveats: it does not intercept data pasted directly into cloud chat, and compression benchmarks are not patch-correctness benchmarks.

Agents need local context infrastructure, not just bigger models.
